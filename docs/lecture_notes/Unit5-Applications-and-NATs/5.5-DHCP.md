
## DHCP

### Getting an IP Address Automatically

Before your laptop can send a single packet, it needs four pieces of configuration: 
- an **IP address**, 
- a **subnet mask**, 
- a **default gateway** (the router), 
- a **DNS server** address.

In the early days of the internet, a network administrator would hand these to you on a slip of
paper. Today, you get them automatically in milliseconds — thanks to **DHCP, the Dynamic Host
Configuration Protocol** (RFC 2131).

### Why Dynamic Configuration?

Static assignment (typing in numbers manually) has three serious problems:

- **Mobility:** if you move your laptop to a different subnet, your old statically-configured
  address is invalid.
- **Scarcity:** IP addresses are finite. You don't want to permanently reserve one for a device
  that's only connected 8 hours a day.
- **Garbage collection:** there's no automatic reclamation; unused addresses accumulate and block
  new devices.

DHCP solves all three: addresses are temporary **leases**, automatically returned when they expire or the device releases them.


A machine can request configuration from a DHCP server
- Movement: just request configuration again
- Configuration has a duration: a “lease,” which can be renewed
- Garbage collection: when lease expires



### The DORA Exchange

Discover, offer, request, ack, release


The DHCP protocol follows a four-message pattern nicknamed **DORA**. 
The bootstrap problem: the client has no IP address yet, so it can't send a unicast packet to anyone. DHCP's elegant solution — use **UDP broadcast** to destination `255.255.255.255`, which reaches every device on
the local network segment.

Diagram: DHCP DORA sequence between a client (no IP), DHCP Server A, and DHCP Server B.
(1) Client broadcasts DISCOVER. 
(2) Both servers respond with OFFER (different addresses).
(3) Client broadcasts REQUEST selecting Server A's offer. 
(4) Server A sends ACK confirming the lease. Server B withdraws its offer upon seeing the REQUEST. 

Client uses the offered address for the duration of the lease, then sends RELEASE when done.

```
Client (no IP)          DHCP Server A          DHCP Server B
    │                        │                       │
    │─── DISCOVER ──────────►│──────────────────────►│   broadcast
    │                        │                       │
    │◄─── OFFER (10.0.0.5) ──│                       │
    │◄─── OFFER (10.0.0.7) ──│───────────────────────│
    │                        │                       │
    │─── REQUEST (10.0.0.5) ►│──────────────────────►│   broadcast
    │                        │                       │
    │◄─── ACK ───────────────│                       │   lease = 24h
```

After receiving the ACK, the client has a fully configured IP address for the duration of the
lease. Before the lease expires, the client sends a renewal REQUEST. If the server doesn't hear
from the client and the lease expires, the address is returned to the pool.

### Technical Details
- UDP ports 67 (server) and 68 (client)
DHCP runs over UDP, using port **67** on the server side and port **68** on the client side.

- Broadcast IP address: 255.255.255.255


- Use relays to forward across links

Because broadcast packets don't cross router boundaries by default, networks use a **DHCP relay agent** — a small forwarding process running on the router that tunnels DHCP messages to a
centralized DHCP server on a different subnet.


> **Key Takeaway:** DHCP elegantly solves the bootstrap problem (getting network config when you
> have no network config yet) by using UDP broadcast. Leases make address allocation both
> automatic and self-healing: devices that leave simply stop renewing, and addresses flow back to
> the pool without administrator intervention.

## Summary

### The Five Things to Remember

1. **HTTP is a text-based request–response protocol over TCP.** HTTP/1.0's
   one-connection-per-request model pays a full TCP handshake cost for every resource, causing
   dramatic slowdowns on pages with many assets. HTTP/1.1's keep-alive eliminates redundant
   handshakes and enables pipelining, achieving ~4× speed improvement on realistic workloads.
   HTTP/2 adds multiplexed streams to eliminate head-of-line blocking.

2. **BitTorrent turns every downloader into an uploader.** Files are split into pieces, each
   hash-verified. Rarest-first selection preserves swarm availability; tit-for-tat choking
   rewards contributors; optimistic unchoking discovers better peers. The endgame strategy
   prevents stalls at the tail of a download.

3. **DHCP solves the bootstrap problem via UDP broadcast.** A device with no IP address
   broadcasts a DISCOVER message, receives OFFERs from servers, selects one with REQUEST, and
   gets a time-limited ACK. Leases make address reclamation automatic.

4. **DNS is a hierarchically-delegated, read-mostly, cached distributed database.** Resolution
   walks the tree from root → TLD → authoritative zone, with caching at each step according to
   TTLs. Glue records break the circular dependency between zone delegation and name resolution.

5. **NAT extends IPv4 by rewriting source IPs and ports at a gateway.** It works transparently
   for outbound connections but fundamentally breaks the ability of external hosts to initiate
   connections to private devices — motivating a family of traversal techniques (hole-punching,
   relays, STUN/TURN) that underlie nearly every modern real-time communication system.
