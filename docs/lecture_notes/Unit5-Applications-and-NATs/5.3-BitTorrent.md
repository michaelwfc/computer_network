# BitTorrent

HTTP is excellent for fetching documents from a server — but if millions of people want the same large file simultaneously, a single server becomes a bottleneck. BitTorrent's solution: **turn every downloader into an uploader**, distributing both the storage and the bandwidth across a self-organizing network of peers.


## Torrent File

- Torrent file (.torrent) describes file to download
  - Names tracker, server tracking who is participating
  - File length, piece length, SHA1 hashes of pieces
  - Additional metadata (who created torrent, etc.)
  - Also specifies tracker


- Client contacts tracker, starts communicating with peers
- “Trackerless” torrents use something called a DHT (distributed hash table)
  - Information on swarm stored across many nodes
  - A distributed coordination mechanism



### Swarms and Pieces

A BitTorrent **swarm** is the collection of all clients currently downloading or seeding a
particular file. The file is broken into fixed-size **pieces** (typically 256 KB–1 MB). Why
pieces instead of one big stream?

1. **Parallelism:** you can download piece 1 from Alice, piece 2 from Bob, and piece 3 from Carol
   simultaneously.
2. **Incremental sharing:** as soon as you finish a piece, you can start uploading it to others —
   even before the full file is done.
3. **Integrity checking:** each piece has a SHA-1 cryptographic hash in the `.torrent` file, so
   you can verify every piece independently after download.

Pieces are further subdivided into smaller **subpieces**, allowing simultaneous download of
different parts of the same piece from different peers, reducing latency to obtain any one piece.

### Finding Peers: Trackers and DHT

To join a swarm, a client needs to know who else is in it. Historically this was done through a
**tracker** — a central server listed in the `.torrent` file. A client announces itself to the
tracker and gets back a list of peer IP:port pairs.

After trackers attracted legal attention, BitTorrent migrated to **trackerless torrents** using a
**Distributed Hash Table (DHT)**. A DHT maps a file's info-hash to the set of peers sharing it,
but the mapping is stored collectively across all participating nodes — no single server holds the
full picture. Think of it as a distributed phone book: any node can look up any entry by asking
its neighbors, who ask their neighbors, until the answer is found.

### What to Download: Rarest First

Peers continuously exchange **bitfields** — bitmaps indicating which pieces each client currently
holds. A smart client downloads the **rarest piece first**: the piece held by the fewest peers in
the swarm.

Why? If only one peer has piece #47 and that peer disappears, nobody can ever complete the file.
By prioritizing rare pieces, the swarm ensures that pieces spread widely before common pieces are
fully replicated, maintaining overall availability.

*Exception:* when a client only needs its last few pieces, it requests each from *multiple* peers
simultaneously (called the **endgame strategy**) to avoid getting stuck waiting for one slow peer
to deliver a final piece.

### Whom to Upload To: Tit-for-Tat

If you uploaded to every peer equally, each of your ~100 TCP connections would be painfully slow.
Instead, BitTorrent uses a **choking** algorithm:

1. Measure the download rate you're receiving from each peer over the last 20 seconds.
2. Pick the *P* best (often P=4) — these are **unchoked** and receive your upload bandwidth.
3. Every ~30 seconds, randomly unchoke one additional peer — an **optimistic unchoke** — to
   discover potentially better partners.

This is a real-world implementation of the game-theory principle of **Tit-for-Tat**: cooperate
with cooperators, defect against defectors. Peers who upload get upload; peers who only leech get
choked.

### BitTyrant: Gaming the System

A 2007 paper introduced **BitTyrant**, a modified client that exploits the standard TFT algorithm:
instead of giving each unchoked peer an equal share of upload bandwidth, BitTyrant gives each peer
*just enough* to remain in their top-P list — freeing the leftover bandwidth to bribe additional
peers into unchoking it. The result: a 70% median improvement in download speed for BitTyrant
users. The paper also showed that if *everyone* used BitTyrant, performance improved slightly
overall — but the biggest gains go to the selfish user when others are cooperative.

> **Key Takeaway:** BitTorrent's three key algorithms — rarest-first piece selection, tit-for-tat
> upload scheduling, and optimistic unchoking — together create a self-sustaining ecosystem where
> contributing is rewarded, availability is maximized, and the load distributes itself across the
> swarm rather than concentrating on any one server.
